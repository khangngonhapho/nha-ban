# US-136: Tọa Độ Bản Đồ Chi Tiết (Map Coordinates Feature)

## User story
**As an** Admin
**I want** to see and edit the exact latitude/longitude coordinates of a listing on the Vercel Admin detail view, and see the map load based on coordinates if available.
**So that** I can pin the exact location of the property on Google Maps, correcting any inaccuracies of text-based address search.

## Acceptance
- [x] **Map Rendering Priority**: If the listing has valid `latitude` and `longitude` (not empty, not `-`), use these coordinates (i.e. `q=${latitude},${longitude}`) instead of searching by `fullAddress`. If coordinates are missing or invalid, fall back to the text address `fullAddress`.
- [x] **UI Display & Edit**: Add "Vĩ độ (Latitude)" and "Kinh độ (Longitude)" input fields in the edit panel, below or next to the address/alley width fields. Populate them with coordinates from `p.latitude`/`p.longitude` or `p.json_ui_parsed.latitude`/`p.json_ui_parsed.longitude`.
- [x] **Curation Save (SQLite)**:
  - When saving locally (Flask endpoint `PUT /api/listings/<tk_id>`), update the database columns `latitude` and `longitude` in tables `listings_v2` and `listings_custom_v2`.
  - For Pool1 mode, since the table `listings` does not have explicit columns for latitude/longitude, save them in the `JSON_UI` field (by parsing, updating `latitude` and `longitude` keys, and serializing back).
- [x] **Sheet Sync & Curation (Google Sheets)**:
  - For Pool1 mode, when saving from the Vercel Admin UI to Google Sheets directly (`saveSourceData` in `static/js/lego_detail_admin.js`), write `latitude` and `longitude` into the `p.json_ui_parsed` object so that it gets serialized into the `JSON_UI` column.
  - For Pool2 mode, update `CUSTOM_HEADERS` and `listings_custom_v2` table creation in `pool_lego.py` to include `latitude` and `longitude`.
- [x] **[ADDITIONAL] Clickable Right-Aligned Map Link**: Instead of embedding the heavy Google Maps iframe, replace it with a right-aligned clickable button/link `📍 Xem định vị trên Google Maps ↗` opening maps in a new tab.
- [x] **[ADDITIONAL] Listing Card Height stretching bugfix**: Constrain card images inside `.ibox img` with `position: absolute` so that tall portrait images do not stretch card heights.

## Solution

### Strategy & Mechanisms
- Tọa độ hiển thị và chỉnh sửa trực tiếp qua panel Admin trên Vercel Admin UI.
- Lưu trữ ở cả 2 chế độ Pool1 (`JSON_UI` field) và Pool2 (`latitude`/`longitude` columns trong `listings_custom_v2`).
- Thay thế iframe Google Maps bằng một liên kết click ngoài (`target="_blank"`) để tối ưu hóa hiệu năng tải trang và hiển thị gọn gàng.
- Sửa lỗi chiều cao card bằng cách định vị tuyệt đối (`position: absolute`) thẻ ảnh bên trong `.ibox`, tránh việc ảnh dọc có kích thước tự nhiên quá dài làm dãn card.

### Configuration
```json
{
  "json_ui_fields": [
    "Criteria_Duong_truoc_nha",
    "Criteria_Loai_BDS",
    "updatedAt",
    "createdAtSigned",
    "Last_Crawl",
    "history",
    "latitude",
    "longitude"
  ]
}
```
